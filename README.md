# PRECISION / Automotive Performance Studio

Рабочий сайт на Next.js 16, React 19 и TypeScript: тёмный motorsport-интерфейс, услуги, портфолио, конфигуратор, заявки, онлайн-запись, клиентский кабинет и управление студией.

## Запуск

Нужен **Node.js 24+**. Используйте существующий checkout `/workspace/first-project`; облачная задача уже изолирована, создавать Git worktree не нужно.

```bash
cd /workspace/first-project
npm ci
npm run dev
```

Production:

```bash
npm run build
npm run start
```

Сервер использует порт 3000; другой порт: `npm run start -- --port 3002`. Работоспособность проверяется через `GET /api/health`. Старые пустые `index.html` и `style.css` сохранены; сайт обслуживает Next.js из `src/app`, а не Python-сервер.

## Что работает

- Главная: cinematic hero, локальный showreel, интерактивные услуги, крупные проекты, сравнение покрытий, PPF, конфигуратор, процесс, материалы, философия и FAQ.
- Портфолио фильтруется по услуге, марке, цвету и кузову без перезагрузки. У проектов отдельные страницы и галереи с увеличением.
- Конфигуратор меняет окрашенные панели схематичной модели, оставляя стекло и колёса неизменными. Фактура, кузов и дополнительные работы влияют на ориентир стоимости.
- PPF-схема показывает семь зон и три пакета; поддерживает мышь, касание и клавиатуру.
- Пятишаговая форма сохраняет заявку и фотографии на сервере. Цена вычисляется повторно на сервере; переданная клиентом сумма не считается достоверной.
- Онлайн-запись показывает доступное время. Транзакция и уникальный индекс предотвращают двойное бронирование. Отмена администратором освобождает слот.
- Регистрация, вход, отзыв сессии и разграничение доступа. Пароли хешируются scrypt; cookie сеанса HttpOnly/SameSite, в production Secure.
- Кабинет: автомобили из заявок, активные проекты и история, этапы работ, согласованные суммы, документы, гарантия и рекомендации.
- Администратор: заявки, CRM-статусы, этапы, сметы, документы, бронирования, клиенты, портфолио, фото, услуги, цены, материалы, отзывы, контакты и журнал интеграций.
- Блог, SEO-страницы услуг, JSON-LD, robots.txt и sitemap.xml. Абсолютные canonical и sitemap появляются после настройки реального `STUDIO_URL`.
- Адаптивность, fullscreen mobile menu, sticky CTA, видимый keyboard focus, native dialogs, reduced motion и сохранение cookie-настроек.

## Данные и администратор

По умолчанию используется **SQLite** через встроенный `node:sqlite`: без дополнительного сервиса для работы в этой облачной среде. Хранение находится в `.data/studio.sqlite`; изображения — в `.data/uploads` (приватные) и `.data/assets` (публичное портфолио). `.data` исключена из Git. WAL и транзакции обеспечивают согласованность записей для одного инстанса.

Не используйте несколько серверов с независимыми каталогами `.data`. Для распределённого развёртывания нужен переход на PostgreSQL и объектное хранилище; эта версия не заявляет такую поддержку. На текущем одиночном сервере данные и загрузки должны располагаться на постоянном диске. При резервном копировании используйте SQLite backup API или остановите сервер и копируйте каталог целиком вместе с WAL.

Создать администратора в интерактивном терминале:

```bash
npm run admin:create
```

Команда спрашивает email, имя и скрытый пароль (минимум 12 символов). Общего пароля и встроенного административного аккаунта нет. Вход — `/account`, управление — `/admin`. Зарегистрированный через сайт пользователь всегда получает роль customer.

Приватные фотографии привязываются к заявке только с токеном загрузки текущего браузера. Уже прикреплённое фото нельзя присвоить другой заявке. Просмотр после привязки доступен администратору и владельцу аккаунта. Анонимные заявки доступны администратору; автоматическая привязка по email не выполняется, чтобы другой человек не мог получить чужие данные через регистрацию.

## Email, AI, CRM и аналитика

Скопируйте `.env.example` в `.env.local` и задайте значения приватно. Секреты не коммитьте и не передавайте в чат.

- **Resend:** `STUDIO_MAIL_KEY` и `STUDIO_MAIL_FROM` с верифицированного домена. Альтернатива — собственный SMTP по переменным `SMTP_*`. Для SMTP нужен настоящий секрет в процессе и разрешённый SMTP-трафик; HTTPS proxy-плейсхолдер не подходит для SMTP.
- **AI:** `STUDIO_AI_KEY`, HTTPS-доступ к `api.openai.com` и модель с поддержкой image edits. Запрос выполняется только после входа, загрузки фото и нажатия кнопки; лимит — три генерации в сутки на пользователя. Реальные запросы без ключа не выполняются. Цветовая схема в конфигураторе работает отдельно от AI.
- **CRM:** `CRM_WEBHOOK_URL` и при необходимости `CRM_WEBHOOK_TOKEN`. Создание заявки и изменение CRM-статуса создают события с уникальным ID. Сторона CRM должна использовать ID для дедупликации. События и ошибки сохраняются в базе; автоматический retry-worker пока не реализован.
- **GA4:** `STUDIO_GA_ID=G-…`. Скрипт не загружается до согласия на аналитику; отказ переводит consent в denied. При отсутствии ID аналитика не запускается.

При ограниченном исходящем доступе добавьте домены выбранных сервисов в настройки среды: `api.resend.com`, `api.openai.com`, hostname вашего CRM; для GA4 в браузере — `www.googletagmanager.com` и `www.google-analytics.com`. Шрифты и автомобильные демонстрационные медиа уже локальны.

Заявки и записи работают без интеграций. Подтверждение честно сообщает, отправлено ли письмо. В журнале: PENDING — подключения нет, SENT — отправка успешна, FAILED — попытка завершилась ошибкой. Подключения к реальному email/AI/CRM не проверены без учётных данных.

## Контент перед запуском бизнеса

Название PRECISION, часы и цены — исходная конфигурация, которую можно изменить в админке. Контакты не выдуманы: пустые поля скрыты. Реальных отзывов в начальной базе нет.

Четыре проекта помечены **CONCEPT PROJECT**. Before/After показывает симуляцию эффекта, а не реальный клиентский кейс. Студийные и клиентские фотографии, реальные отзывы, сведения об операторе данных и финальные юридические тексты нужно предоставить перед публичным запуском. Собственные визуальные иллюстрации и видеомонтаж описаны в [docs/media.md](docs/media.md). Для публикации реальных кейсов загрузите фотографии выполненных работ.

## Проверки

```bash
npm run typecheck
npm test
npm run build
npm run test:integration
npm run test:ui
```

API- и браузерные проверки создают отдельные временные базы. SMTP, Resend, CRM и AI в них отключены; тестовые письма не отправляются. Проверяется поведение, включая ошибки, права доступа, недоверенные цены и конфликт записей.

Playwright использует системный `/usr/bin/chromium`, если он установлен. На другой машине сначала выполните `npx playwright install chromium`. UI-проверки включают смартфон с touch и reduced motion, взаимодействия форм и скриншоты. `/workspace/precision-preview/desktop.png` и `mobile.png` — артефакты проверки текущей облачной среды.

Описание структуры и сценариев — [docs/architecture.md](docs/architecture.md).
